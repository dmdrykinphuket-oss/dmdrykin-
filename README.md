# Телеграм-бот с Claude

Бот отвечает на сообщения через модель `claude-sonnet-5`, хранит историю по каждому
пользователю (последние 20 сообщений), пускает только разрешённых пользователей и
не падает при ошибках API.

## Установка

```powershell
python -m pip install -r requirements.txt
```

Для голосовых сообщений нужен **ffmpeg** в PATH (Windows: `winget install Gyan.FFmpeg`).
При первом голосовом бот один раз скачает модель распознавания речи
faster-whisper `small` (~460 МБ) в `~/.cache/huggingface`.

## Настройка

Откройте файл `.env` и впишите три значения:

| Переменная          | Где взять                                                        |
|---------------------|-----------------------------------------------------------------|
| `TELEGRAM_TOKEN`    | Напишите `@BotFather` в Telegram → `/newbot` → скопируйте токен  |
| `ANTHROPIC_API_KEY` | https://console.anthropic.com/ → API Keys → Create Key          |
| `ALLOWED_USERS`     | Ваш Telegram ID — узнать у `@userinfobot`. Несколько — через запятую |

Необязательные переменные:

| Переменная          | Зачем                                                            |
|---------------------|-----------------------------------------------------------------|
| `OPENAI_API_KEY`    | Расшифровка голосовых через OpenAI Whisper API (иначе — локальная модель) |
| `CLICKUP_TOKEN`     | Личный токен ClickUp (ClickUp → Settings → Apps → API Token, вид `pk_...`) — включает работу с задачами |
| `CLICKUP_LIST_ID`   | ID списка ClickUp, куда бот создаёт задачи (из URL списка `.../li/<id>`) |
| `CLICKUP_TEAM_ID`   | ID рабочего пространства (число в URL после `app.clickup.com/`). Если задан — список задач читается по всему пространству, а не только из `CLICKUP_LIST_ID` |

`CLICKUP_TOKEN` и `CLICKUP_LIST_ID` нужны вместе — если хоть одной нет,
инструменты работы с задачами просто отключаются, остальной бот работает как обычно.
`CLICKUP_TEAM_ID` необязателен: без него список задач ограничен `CLICKUP_LIST_ID`.
Создание задач всегда идёт в `CLICKUP_LIST_ID`.

Пример заполненного `.env`:

```
TELEGRAM_TOKEN=8123456789:AAF...пример...xyz
ANTHROPIC_API_KEY=sk-ant-...пример...
ALLOWED_USERS=123456789,987654321
CLICKUP_TOKEN=pk_12345678_ABC...пример...
CLICKUP_LIST_ID=901234567890
CLICKUP_TEAM_ID=9012345
```

Файл `.env` уже добавлен в `.gitignore` — он не попадёт в git.

## Запуск

```powershell
python bot.py
```

Бот работает, пока открыто окно терминала. Остановить — `Ctrl + C`.
Если `Ctrl + C` не помог — закрыть все процессы Python:
`Get-Process python* | Stop-Process -Force`

Если сеть на старте недоступна или бот неожиданно упадёт во время работы —
он сам перезапускается (без вмешательства), кроме случаев ошибки конфигурации
(нет токена в `.env` и т.п. — тогда процесс завершается насовсем).

Запускать бота нужно **в одном экземпляре**: два одновременно работающих процесса
с одним токеном конфликтуют, и бот перестаёт отвечать.

## Команды бота

- любое текстовое сообщение — бот отвечает через Claude, при необходимости ищет в интернете и показывает ссылки на источники;
- **файл PDF, DOCX или TXT** — бот извлекает текст, подтверждает приём и размер, после чего можно задавать несколько вопросов подряд по этому документу;
- **изображение** — фото из телеграма или картинка, присланная файлом (`jpg`, `png`, `webp`):
  - если у фото есть подпись — она уходит модели как вопрос/задача по картинке; если подписи нет — бот просто рассматривает и комментирует изображение;
  - картинка остаётся в контексте — по ней можно задать несколько вопросов подряд (как с документом); в контексте держится не больше `MAX_IMAGES_IN_CONTEXT` (по умолчанию 4) изображений, новые вытесняют самые старые;
  - если фото пришло **альбомом** — все кадры уходят модели одним запросом;
  - из нескольких размеров, которые присылает Telegram, берётся самый большой; лимит на изображение — `MAX_IMAGE_SIZE_MB` (по умолчанию 5 МБ, ограничение API);
  - `/forget` убирает из контекста и документ, и изображения;
- **голосовое сообщение или аудиофайл** (m4a, mp3, ogg, wav… — в том числе присланные «документом») — бот расшифровывает запись локально (faster-whisper, модель `small`, русский), затем прогоняет текст через `claude-sonnet-5`:
  - **вычищенный текст** — исправлены орфография и пунктуация, убраны слова-паразиты и повторы, расставлены абзацы (смысл и формулировки не меняются);
  - если сырая расшифровка длиннее 400 символов — **структурное резюме**: суть одной строкой, ключевые пункты, отдельно договорённости и задачи (блок не выводится, если его в записи нет).

  Сырая расшифровка сохраняется, но в чат не выводится — её показывает команда `/raw`. Если обработка через модель не удалась, бот покажет сырую расшифровку с пометкой. Лимиты: 120 секунд (`MAX_VOICE_SECONDS`), 10 МБ (`MAX_FILE_SIZE_MB`), порог резюме — `TRANSCRIPT_SUMMARY_THRESHOLD`;
- **выгрузка длинных ответов файлом** — любой ответ модели (обычный чат или `/tr`) длиннее 3000 символов (`FILE_THRESHOLD`) приходит файлом `.docx` вместо текста: заголовки, списки и таблицы переносятся в форматирование Word, а не остаются символами разметки; в подписи к файлу — первые пара абзацев ответа, чтобы была видна суть без открытия файла; имя файла — по присланному документу (если он был) или дате-времени;
  - `/file` — принудительно отдать последний ответ файлом, даже если он короткий;
  - `/nofile` — выключить автовыгрузку файлом до конца сессии (перезапуска бота) — дальше всегда текстом, `/file` по-прежнему работает вручную;
- **задачи ClickUp** (если заданы `CLICKUP_TOKEN` и `CLICKUP_LIST_ID`) — попросите бота обычными словами: «поставь задачу … до пятницы», «покажи задачи», «что просрочено в списке Маркетинг», «покажи задачу abc123». Три инструмента у модели:
  - `clickup_create_task` — создаёт задачу в списке по умолчанию. Срок понимает по-человечески («завтра», «до пятницы», «через 3 дня», «15 сентября», `2026-09-20`). **Задача не создаётся сразу**: бот показывает черновик (название, описание, срок) и создаёт только после явного «да», затем присылает ссылку на задачу. Явное «нет»/«отмена» — снимает черновик; любое другое сообщение бот обрабатывает как обычно, а черновик сохраняет и напоминает о нём. Если за 15 минут (`CLICKUP_CONFIRM_TIMEOUT_SECONDS`) подтверждения не было — черновик снимается сам;
  - `clickup_list_tasks` — список задач. С `CLICKUP_TEAM_ID` читает задачи по всему рабочему пространству (все списки), без него — только из `CLICKUP_LIST_ID`. Фильтры (все необязательны): статус (`open`, `in progress`, `closed`…; `all` — со всеми, включая закрытые), срок (`просроченные`, `сегодня`, `завтра`, `неделя`, `без срока`), список (часть названия или числовой ID). По умолчанию показываются только незакрытые задачи; у каждой задачи в выводе указан её список;
  - `clickup_get_task` — подробности одной задачи по её ID.

  Инструментов на **изменение и удаление** задач намеренно нет. Ошибки ClickUp API бот показывает текстом в чат, не замалчивает;
- `/raw` — сырая расшифровка последнего голосового/аудио;
- `/history` — сколько сообщений сохранено в истории;
- `/forget` — убрать документ и изображения из контекста;
- `/reset` — очистить историю диалога текущего пользователя;
- `/start` — приветствие и список команд.

Вся переписка хранится в SQLite-файле `history.db` рядом с ботом и переживает
перезапуск — бот продолжает диалог с того места, где остановились. Модели при этом
всегда передаются только последние 20 сообщений (`MAX_HISTORY_MESSAGES` в `bot.py`).
Файл `history.db` добавлен в `.gitignore` и в git не попадает.

Ограничения по файлам: максимум **10 МБ**, модели передаётся до ~120 тыс. символов текста
(настраивается константами `MAX_FILE_SIZE_MB` и `MAX_DOC_CHARS` в `bot.py`).
Документы кроме PDF/DOCX/TXT, картинок и аудио, а также видео — бот вежливо отклоняет.

Пользователям не из списка `ALLOWED_USERS` бот вежливо отказывает.

## Логи

Бот пишет в `bot_run.log` (файл в `.gitignore`, в git не попадает) и в
системный журнал (`journalctl -u tgbot`). В эти логи попадают **только
метаданные обработки**: id пользователя, тип запроса, объём (символы,
байты, токены) и результат. Тексты сообщений, расшифровки голосовых и
ответы модели в лог **не пишутся** — вся переписка хранится только в
`history.db`. Отдельно, в `requests.log` — по одной строке на каждое
обращение к модели (объём контекста, модель, `stop_reason`, результат).
