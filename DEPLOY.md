# Перенос бота на VPS (Ubuntu 24.04)

Пошаговая инструкция: с чего локально (на Windows) до работающего бота на
сервере, который сам стартует при перезагрузке сервера и сам поднимается
при падении.

Сервер в примерах: `168.144.242.14` (DigitalOcean, Ubuntu 24.04).
Дальше замените `<username>` на ваш логин на GitHub и `<repo>` — на имя
репозитория, который создадите на шаге 1.

Бот работает по **long polling** — сам ходит к Telegram за сообщениями,
а не наоборот. Поэтому открывать входящие порты в файрволе сервера
**не нужно** — исходящих соединений (к Telegram, к Anthropic и к OpenAI)
достаточно.

---

## Часть 1. Локально (на этом компьютере): публикация на GitHub

### 1.1 Создать репозиторий на GitHub

Откройте https://github.com/new и создайте репозиторий:
- имя — например `tgbot`;
- видимость — **Private** (в коде секретов нет — `.env` в `.gitignore` — но
  без причины светить исходники личного бота не стоит);
- **ничего не отмечайте** (ни README, ни .gitignore, ни license) — эти файлы
  уже есть локально, и если GitHub создаст свои, при первом push будет
  конфликт.

Нажмите «Create repository» — GitHub покажет пустую страницу с адресом
репозитория (`https://github.com/<username>/<repo>.git`) — он понадобится
на следующем шаге.

### 1.2 Отправить код на GitHub

В терминале, в папке проекта:

```powershell
git remote add origin https://github.com/<username>/<repo>.git
git push -u origin main
```

- `remote add origin` — говорит git, куда отправлять код (адрес репозитория
  с шага 1.1).
- `push -u origin main` — отправляет ветку `main`; `-u` запоминает связку,
  чтобы дальше можно было писать просто `git push`.

При первом push Git для Windows обычно сам откроет окно браузера — войдите
в свой аккаунт GitHub и разрешите доступ. Пароль вручную вводить не
придётся.

Проверьте на странице репозитория на GitHub, что файлы появились — включая
`tgbot.service`, `requirements.txt`, `.env.example`, `DEPLOY.md`.

## Часть 2. На сервере (в вашем SSH-окне)

Дальше — команды, которые нужно выполнить в SSH-сессии к
`168.144.242.14`. Где сказано «от имени tgbot» — вы уже переключились на
этого пользователя (шаг 2.3); где не сказано — команды от вашего исходного
пользователя (обычно `root`, с `sudo`).

### 2.1 Обновить систему и поставить нужные пакеты

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y python3 python3-venv python3-pip git ffmpeg
```

- `apt update` — обновляет список доступных пакетов (не сами пакеты).
- `apt upgrade -y` — ставит обновления уже установленных пакетов
  (`-y` — не переспрашивать подтверждение).
- `apt install`: `python3` — интерпретатор Python (в Ubuntu 24.04 это
  версия 3.12 — боту этого достаточно); `python3-venv` — модуль для
  создания изолированного виртуального окружения; `python3-pip` — менеджер
  пакетов Python; `git` — чтобы скачать код с GitHub; `ffmpeg` — на всякий
  случай для распознавания голосовых (обычно хватает и без него, но пусть
  будет — meньше шансов на странности с конкретным форматом аудио).

Проверьте объём памяти на сервере — `free -h`. Если задан `OPENAI_API_KEY`
(см. шаг 2.6), голосовые расшифровываются в облаке OpenAI и локальная модель
не грузится вообще. Но запасной путь (`faster-whisper`, small) всё равно
включится, если запрос к OpenAI не пройдёт, — а эта модель при работе
занимает около 1 ГБ. Поэтому, если у дроплета 1 ГБ RAM или меньше, всё
равно стоит добавить файл подкачки (swap), иначе загрузка модели на
запасном пути может уронить процесс по нехватке памяти:

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

(если памяти 2 ГБ и больше — этот блок можно пропустить).

### 2.2 Создать отдельного пользователя для бота

Бот не должен работать от root — лишние права ему не нужны, а в случае
уязвимости в какой-нибудь зависимости это лишний риск.

```bash
sudo adduser --system --group --home /opt/tgbot --shell /bin/bash tgbot
```

Создаёт системного пользователя `tgbot` (без обычного входа в систему по
паролю) со своей домашней папкой `/opt/tgbot` — туда и ляжет код бота.

### 2.3 Ключ для доступа к приватному репозиторию (deploy key)

Переключаемся на пользователя tgbot и создаём для него отдельный SSH-ключ
— специально для скачивания этого одного репозитория, без доступа куда-то
ещё:

```bash
sudo su - tgbot
ssh-keygen -t ed25519 -C "tgbot-deploy" -f ~/.ssh/id_ed25519 -N ""
cat ~/.ssh/id_ed25519.pub
```

- `sudo su - tgbot` — «пересаживает» вас в сессию пользователя tgbot (для
  выхода обратно наберите `exit`).
- `ssh-keygen` — генерирует пару ключей (`-N ""` — без пароля на сам ключ,
  чтобы бот мог работать без интерактивного ввода).
- `cat ... .pub` — печатает публичный ключ. Скопируйте всю строку целиком
  (начинается с `ssh-ed25519`).

На GitHub: откройте репозиторий → **Settings → Deploy keys → Add deploy
key**. Вставьте скопированный ключ, «Allow write access» **не** включайте
(боту нужно только скачивать код, не отправлять). Сохраните.

Проверка, что ключ работает:

```bash
ssh -T git@github.com
```

Ответ вида `Hi <repo>! You've successfully authenticated, but GitHub does
not provide shell access.` — это нормально, не ошибка (просто GitHub
подтверждает, что вас узнал).

### 2.4 Скачать код бота

Всё ещё от имени tgbot:

```bash
cd /opt/tgbot
git clone git@github.com:<username>/<repo>.git .
```

Точка в конце — клонировать прямо в текущую папку (`/opt/tgbot`), а не
создавать вложенную подпапку.

### 2.5 Виртуальное окружение и зависимости

```bash
python3 -m venv venv
venv/bin/pip install --upgrade pip
venv/bin/pip install -r requirements.txt
```

- `python3 -m venv venv` — создаёт изолированное окружение Python в папке
  `venv` (библиотеки бота не смешиваются с системным Python).
- `pip install --upgrade pip` — обновляет сам pip (со старым pip иногда
  бывают проблемы со сборкой некоторых пакетов).
- `pip install -r requirements.txt` — ставит все зависимости бота. Займёт
  несколько минут — `faster-whisper` тянет за собой увесистые пакеты
  (`ctranslate2`, `onnxruntime`).

### 2.6 Настроить .env

```bash
cp .env.example .env
nano .env
```

Впишите реальные значения: `TELEGRAM_TOKEN` (от @BotFather),
`ANTHROPIC_API_KEY` (с console.anthropic.com), `ALLOWED_USERS` (ваш
Telegram ID). Сохранить в nano — `Ctrl+O`, `Enter`, выйти — `Ctrl+X`.

Голосовые сообщения расшифровываются через **OpenAI Whisper API** — для
этого добавьте в `.env` ещё и `OPENAI_API_KEY` (ключ с
https://platform.openai.com/api-keys). Строка уже есть в `.env.example` —
достаточно вписать значение.

Ключ **необязательный**: если его не задать (или если запрос к OpenAI не
пройдёт), бот сам переключится на локальную модель `faster-whisper` — как
работало раньше. В ответ на голосовое бот пишет пометку, каким способом
сделана расшифровка, так что переключение на запасной вариант видно сразу.
Если ключ OpenAI задан и работает, локальная модель на сервер не
скачивается и память не занимает.

### 2.7 Проверить, что бот стартует вручную

```bash
venv/bin/python bot.py
```

В логе должно появиться `Бот запущен. Разрешённые пользователи: [...]` —
значит всё настроено верно. Напишите боту в Telegram что-нибудь, чтобы
убедиться, что отвечает. Остановите — `Ctrl+C`.

Если вместо этого ошибка про `TELEGRAM_TOKEN`/`ANTHROPIC_API_KEY` — значит
`.env` не заполнен или лежит не в `/opt/tgbot`.

### 2.8 Вернуться к своему пользователю и включить systemd-сервис

```bash
exit
```
(это выход из сессии tgbot обратно к вашему пользователю с `sudo`)

```bash
sudo cp /opt/tgbot/tgbot.service /etc/systemd/system/tgbot.service
sudo systemctl daemon-reload
sudo systemctl enable tgbot
sudo systemctl start tgbot
```

- `cp ... /etc/systemd/system/` — кладёт файл юнита туда, где его видит
  systemd.
- `daemon-reload` — просит systemd перечитать список юнитов (иначе он не
  увидит новый файл).
- `enable` — включает автозапуск бота при каждой загрузке сервера.
- `start` — запускает бота прямо сейчас.

### 2.9 Проверить, что всё работает

```bash
sudo systemctl status tgbot
```

Ищите строку `Active: active (running)`. Если там `failed` — смотрите лог:

```bash
sudo journalctl -u tgbot -f
```

Показывает лог бота в реальном времени (аналог `tail -f`). Выход — `Ctrl+C`.
Если всё в порядке, напишите боту в Telegram `/start` — должен ответить.

## Обновление бота в будущем

Когда локально появятся новые изменения и вы их закоммитите и запушите на
GitHub — на сервере:

```bash
cd /opt/tgbot
sudo -u tgbot git pull
sudo -u tgbot venv/bin/pip install -r requirements.txt
sudo systemctl restart tgbot
```

`pip install -r requirements.txt` можно пропускать, если зависимости
(`requirements.txt`) не менялись — но лишним не будет: если ничего не
изменилось, команда просто ничего не поставит заново.

> **Обновление с расшифровкой через OpenAI Whisper.** В этой версии
> добавилась зависимость `openai` и новая переменная окружения. После
> `git pull` обязательно выполните `venv/bin/pip install -r
> requirements.txt` и допишите в `/opt/tgbot/.env` строку:
>
> ```
> OPENAI_API_KEY=<ключ с https://platform.openai.com/api-keys>
> ```
>
> Затем `sudo systemctl restart tgbot`. Без ключа бот тоже запустится, но
> голосовые будет расшифровывать локальной моделью, как раньше.
> Отредактировать `.env` от имени бота: `sudo -u tgbot nano
> /opt/tgbot/.env`.

### Если под рукой нет SSH

Например, ключа нет на чужом компьютере или SSH заблокирован. Зайти на
сервер можно через **веб-консоль DigitalOcean**: панель → нужный дроплет →
кнопка **Console** (вверху справа) или **Access → Launch Droplet Console**.
Откроется терминал прямо в браузере — вход по логину/паролю пользователя
сервера (обычно `root`).

Дальше — те же команды, что и по SSH:

```bash
cd /opt/tgbot
sudo -u tgbot git pull
sudo systemctl restart tgbot
systemctl status tgbot --no-pager
```

Ищите `Active: active (running)`. Веб-консоль не закрывайте, пока не
убедились, что бот поднялся и отвечает в Telegram.

## Если что-то не так

- **`sudo systemctl status tgbot` показывает частые перезапуски
  (`activating (auto-restart)` туда-сюда)** — смотрите `sudo journalctl -u
  tgbot -n 50` (последние 50 строк лога) — там будет настоящая причина
  (чаще всего — опечатка в `.env` или не поставились зависимости).
- **Бот не отвечает, но `systemctl status` говорит `running`** — проверьте
  интернет с сервера (`curl -I https://api.telegram.org`) и правильность
  `TELEGRAM_TOKEN`.
- **Нужно посмотреть логи каждого обращения к модели** — файл
  `/opt/tgbot/requests.log`, как и на Windows.
